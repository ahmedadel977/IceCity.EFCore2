# استراتيجيات تحميل البيانات (Loading Strategies) في Entity Framework Core

## ما المقصود بـ Loading؟

عند جلب كيان (Entity) من قاعدة البيانات، قد تحتاج أيضًا إلى جلب البيانات المرتبطة به (Navigation Properties).

مثال:

Owner
 └── Houses
      └── Heaters
           └── DailyUsages

يوفر Entity Framework Core ثلاث طرق لتحميل هذه البيانات.

---

# أولًا: Eager Loading

## التعريف

يقوم بجلب الكيان الأساسي وجميع البيانات المرتبطة به في **استعلام واحد** باستخدام `Include()` و `ThenInclude()`.

## مثال

```csharp
var owners = context.Owners
    .Include(o => o.Houses)
        .ThenInclude(h => h.Heaters)
            .ThenInclude(h => h.DailyUsages)
    .ToList();
```

## المميزات

- تنفيذ استعلام واحد فقط.
- أداء ممتاز عند الحاجة لكل البيانات.
- الأكثر استخدامًا في المشاريع الحقيقية.

## العيوب

- قد يجلب بيانات لا تحتاجها.
- إذا كانت العلاقات كثيرة قد يصبح الاستعلام كبيرًا.

## يستخدم عندما

تكون تعلم مسبقًا أنك تحتاج جميع البيانات المرتبطة.

---

# ثانيًا: Explicit Loading

## التعريف

يتم جلب الكيان الأساسي أولًا، ثم تحميل البيانات المرتبطة يدويًا عند الحاجة باستخدام `Load()`.

## مثال

```csharp
var owner = context.Owners.First();

context.Entry(owner)
       .Collection(o => o.Houses)
       .Load();
```

## المميزات

- تحكم كامل في البيانات التي يتم تحميلها.
- يقلل تحميل البيانات غير المطلوبة.

## العيوب

- ينفذ أكثر من استعلام.
- يحتاج إلى كتابة كود أكثر.

## يستخدم عندما

لا تكون متأكدًا أنك ستحتاج البيانات المرتبطة.

---

# ثالثًا: Lazy Loading

## التعريف

يقوم EF Core بتحميل البيانات المرتبطة تلقائيًا عند أول محاولة للوصول إليها.

## مثال

```csharp
var owner = context.Owners.First();

foreach(var house in owner.Houses)
{
    Console.WriteLine(house.Address);
}
```

عند الوصول إلى `owner.Houses` يقوم EF Core بتنفيذ استعلام تلقائي.

## المميزات

- سهل جدًا في الكتابة.
- يحمل البيانات عند الحاجة فقط.

## العيوب

- قد يسبب مشكلة **N+1 Query**.
- يصعب معرفة عدد الاستعلامات المنفذة.
- نادر الاستخدام في المشاريع الكبيرة.

## المتطلبات

- تثبيت Microsoft.EntityFrameworkCore.Proxies
- تفعيل UseLazyLoadingProxies()
- جعل الـ Navigation Properties من النوع virtual

---

# مقارنة بين الأنواع

| النوع | عدد الاستعلامات | الأداء | الاستخدام |
|--------|-----------------|---------|-----------|
| Eager Loading | استعلام واحد | ممتاز | الأكثر استخدامًا |
| Explicit Loading | أكثر من استعلام | جيد جدًا | عند الحاجة |
| Lazy Loading | تلقائي | قد يكون ضعيفًا | نادر الاستخدام |

---

# أفضل الممارسات

✅ استخدم **Eager Loading** عندما تعرف مسبقًا البيانات التي تحتاجها.

✅ استخدم **Explicit Loading** عندما تكون البيانات المرتبطة اختيارية.

❌ تجنب **Lazy Loading** في المشاريع الكبيرة لأنه قد يسبب مشكلة **N+1 Query Problem** ويؤثر على الأداء.

---

# الخلاصة

- **Eager Loading**: يجلب كل البيانات المطلوبة من البداية باستخدام `Include()` و`ThenInclude()`.
- **Explicit Loading**: يجلب البيانات المرتبطة يدويًا عند الحاجة باستخدام `Load()`.
- **Lazy Loading**: يجلب البيانات تلقائيًا عند الوصول إليها لأول مرة، لكنه قد يسبب مشاكل في الأداء.

**في أغلب مشاريع ASP.NET Core وEF Core الاحترافية، يكون Eager Loading هو الخيار الأول، ويستخدم Explicit Loading في حالات خاصة، بينما يستخدم Lazy Loading بحذر.**
